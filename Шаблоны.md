## 1. Ввод/вывод под CodeRun

**Когда:** всегда. Это первая строка любой задачи. Держится в мышечной памяти, не отнимает тактов на разбор.

**Ключевое:** один `read().split()` — сразу токены. Никаких `input()` в цикле (медленно на больших входах).

```python

    # ... логика ...

    print(ans)

solve()
```

**Полезные разборы:**
- `int(data[i])` — одно число
- `list(map(int, data[k:k+n]))` — массив из n чисел, начиная с k
- строку: `data[i].decode()` (токены — байты)

**Где наступают баги:**
- Забыл `int()` / `decode()` — работаешь с байтами вместо чисел/строк.
- Перепутал смещение в `data[k:k+n]` — съехал на индексе.

## 2. Бинпоиск по ответу

**Когда узнавать:**
- «Максимизируй минимум» / «минимизируй максимум».
- Можно задать вопрос: **«результат не хуже x достижим?»** — и этот вопрос *проще* исходного.
- Проверка **монотонна**: если `x` достижим, то соседние тоже.

**Инвариант (главное):**
```
Минимум:  check(l) = False   check(r) = True   →  ответ = r
Максимум: check(l) = True    check(r) = False  →  ответ = l
```
Границы выбираешь так, чтобы инвариант держался с самого начала.

### Ищем МИНИМАЛЬНЫЙ ответ

```python
def check(x):
    # True, если результат НЕ ХУЖЕ x достижим.
    # ТЕЛО ПОД ЗАДАЧУ.
    return False

l = 0                    # check(l) == False
r = 10**18               # check(r) == True
while l + 1 < r:
    m = (l + r) // 2
    if check(m):
        r = m
    else:
        l = m
print(r)                 # ответ = r
```

### Ищем МАКСИМАЛЬНЫЙ ответ

```python
def check(x):
    # True, если результат ДОСТИГАЕТ x.
    return False

l = 0                    # check(l) == True
r = 10**18               # check(r) == False
while l + 1 < r:
    m = (l + r) // 2
    if check(m):
        l = m
    else:
        r = m
print(l)                 # ответ = l
```

**Где наступают баги:**
- Сломанный инвариант: выбрал `l` с неправильным `check` — цикл ломается сразу.
- `while l < r` вместо `l + 1 < r` → бесконечный цикл.
- `check` не монотонен → бинпоиск врёт (это про условие, не про код).

## 3. DFS / BFS

**Когда узнавать:**
- Структура «граф» (связи, соседства, сетка-лабиринт) + нужен обход, связность, пути, компоненты.
- DFS — связность, циклы, топсорт, поиск в глубину. BFS — **кратчайшее по числу рёбер**, распространение волнами.

**Ключевое:** `visited` — чтобы не зайти дважды. Список смежности `g[v]` — соседи вершины `v`.

### DFS (через стек, без рекурсии — безопасно по памяти)

```python
def dfs(start):
    visited = [False] * n
    stack = [start]
    visited[start] = True
    while stack:
        v = stack.pop()
        for to in g[v]:
            if not visited[to]:
                visited[to] = True
                stack.append(to)
```

### BFS (кратчайшее по числу рёбер)

```python
from collections import deque

def bfs(start):
    dist = [-1] * n
    dist[start] = 0
    q = deque([start])
    while q:
        v = q.popleft()
        for to in g[v]:
            if dist[to] == -1:
                dist[to] = dist[v] + 1
                q.append(to)
```

**Где наступают баги:**
- Забыл пометить `visited[start]`/`dist[start]` до цикла — заходишь в старт дважды.
- Помечаешь посещение **при извлечении** из очереди, а не при добавлении → дубли в очереди, TL.
- DFS через рекурсию на большом графе → `RecursionError`. Поэтому тут стек.

## 4. Дейкстра (кратчайший путь, неотрицательные веса)

**Когда узнавать:**
- Взвешенный граф (у рёбер есть длина/стоимость), веса ≥ 0, нужен кратчайший путь от одной вершины ко всем.

**Ключевое:** приоритетная очередь (`heapq`), расслабляем рёбра, `dist[v]` — текущая лучшая оценка.

```python
import heapq

def dijkstra(start):
    INF = float('inf')
    dist = [INF] * n
    dist[start] = 0
    pq = [(0, start)]                 # (расстояние, вершина)
    while pq:
        d, v = heapq.heappop(pq)
        if d > dist[v]:               # устаревшая запись — пропускаем
            continue
        for to, w in g[v]:            # g[v] = список (сосед, вес)
            nd = d + w
            if nd < dist[to]:
                dist[to] = nd
                heapq.heappush(pq, (nd, to))
    return dist
```

**Где наступают баги:**
- Нет проверки `if d > dist[v]: continue` → обрабатываешь устаревшие записи, TL.
- Кладёшь в очередь `(v, d)` вместо `(d, v)` → сортировка по вершине, а не по расстоянию — алгоритм ломается.
- Граф с отрицательными рёбрами → Дейкстра не работает, нужен Беллман-Фор/Форд-Беллман.

## 5. DSU (система непересекающихся множеств)

**Когда узнавать:**
- «Объединить группы», «принадлежат ли одному множеству», остовное дерево (Краскал), связность при добавлении рёбер.

**Ключевое:** `find` с **сжатием путей**, `union` по **рангу**. Обе оптимизации вместе дают ~O(1) амортизированно.

```python
parent = list(range(n))
rank = [0] * n

def find(x):
    # итеративно + сжатие путей
    root = x
    while parent[root] != root:
        root = parent[root]
    while parent[x] != root:          # сжатие: все на пути → к root
        parent[x], x = root, parent[x]
    return root

def union(a, b):
    a, b = find(a), find(b)
    if a == b:
        return False                  # уже в одном множестве
    if rank[a] < rank[b]:
        a, b = b, a
    parent[b] = a
    if rank[a] == rank[b]:
        rank[a] += 1
    return True
```

**Где наступают баги:**
- Забыл сжатие путей или ранг → медленно, TL на больших тестах.
- `find` через рекурсию на длинных цепочках → `RecursionError` (поэтому тут итеративный).
- `union` без проверки `a == b` → ранг портится.

## 6. Префиксные суммы (1D и 2D)

**Когда узнавать:**
- Много запросов «сумма на отрезке `[l, r]`» / «сумма в прямоугольнике» → пересчитывать каждый раз дорого, нужна предподсчёт за O(1) на запрос.

### 1D

```python
# предподсчёт: pref[i] = сумма a[0..i-1], pref[0] = 0
pref = [0] * (n + 1)
for i in range(n):
    pref[i + 1] = pref[i] + a[i]

# сумма на [l, r] (включительно)
def sum_lr(l, r):
    return pref[r + 1] - pref[l]
```

### 2D

```python
# pref[i][j] = сумма в прямоугольнике (0,0)..(i-1,j-1)
pref = [[0] * (m + 1) for _ in range(n + 1)]
for i in range(n):
            row = 0
    for j in range(m):
        row += a[i][j]
        pref[i + 1][j + 1] = pref[i][j + 1] + row

# сумма в прямоугольнике [r1..r2] x [c1..c2] (включительно)
def sum_rect(r1, c1, r2, c2):
    return (pref[r2 + 1][c2 + 1]
            - pref[r1][c2 + 1]
            - pref[r2 + 1][c1]
            + pref[r1][c1])
```

**Где наступают баги:**
- Размер `(n+1)` для `pref` — забыл `+1` → вылет за границу или off-by-one в сумме.
- В 2D перепутал знаки включения/исключения в формуле включения-исключения.
- Считал `pref` «внутри» запроса вместо предподсчёта → TL.

## 7. Два указателя

**Когда узнавать:**
- Массив/строка + вопрос про пару/отрезок с условием. Один указатель двигается вперёд, другой отстаёт.
- Сортированный массив + «найти пару с суммой», «длиннейший отрезок с условием», «найти k-е что-то».

**Ключевое:** оба указателя двигаются только вперёд → O(n) вместо O(n²). Условие должно быть **монотонным** (расширение отрезка сохраняет выполнимость / сужение — наоборот).

```python
def two_pointers(a, k):

        while УСЛОВИЕ_СЖАТИЯ:          # пока окно нарушает условие
            # убрать a[l] из state
            l += 1

        # обновить best по текущему окну
    return best
```

**Где наступают баги:**
- Указатели двигаются не только вперёд → O(n²), а не O(n).
- Забыл убрать `a[l]` из `state` при сжатии → состояние рассинхронизировано.
- Условие не монотонно → алгоритм врёт (пропускает верные окна).
